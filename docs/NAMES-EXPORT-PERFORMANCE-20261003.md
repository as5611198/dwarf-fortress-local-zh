# 載入存檔後 2–4 FPS：名稱匯出回歸

2026-10-03，以玩家當時載入且暫停的 `autosave 1`、要塞主畫面實測。
實際安裝版本為 0.5.21；此次只套用本機 Lua 修正，沒有另發新版本。

## 根因與版本邊界

直接比較 0.4.1 與 0.5.0 發布 ZIP：0.4.1 的 names-worker 直接解碼文字；
0.5.0 改成在每筆名稱的 `text()` 中呼叫 `reqscript('df-local-zh-unicode')`。
DFHack 的 reqscript 即使模組已載入，也會查找腳本與探測檔案修改時間。
每個人物至少處理原文與英文兩次；匯出器每次更新處理 64 筆，因此持續大量查檔。
世界載入後才開始匯出，遊戲暫停時仍執行，符合主選單正常而存檔掉幀的現象。

## 隔離證據

- 世界有 51,389 個歷史人物，實際圖形 FPS 為 3–4，pause_state=true。
- 25,985 ms 的 DFHack 計數中，Lua timers 使用 25,639 ms（98.67%）；疊圖為 141 ms。
- 40 次更新、9,391 ms 的回呼計時中，names-worker 的 step 執行 39 次、共 9,187 ms，最長 250 ms。
- 同畫面的 unit-text、runtime.poll、Legends reader 等取樣耗時均低於毫秒計時解析度；先前直接歸因於 unit-text 的紀錄不足以解釋這次要塞主畫面問題。
- 128 次「查找 Unicode 模組再解碼」花 218 ms；重用模組解碼花 0 ms（低於計時解析度，不代表零成本）。
- 暫時只對 names-worker 快取該模組，100 次更新花 172 ms；測試後還原。稍後原匯出工作完成，FPS 回到 50，玩家同時確認。

## 修正與驗證

把 Unicode 模組解析移到 names-worker 模組初始化，逐筆使用已載入的解碼器。
保留 Unicode／CP437 判斷、64 筆增量處理、名稱與別名輸出，不停用翻譯功能。

`self-tests/names-worker-performance.lua` 對真正的 names-worker 及 Unicode 解碼器測試：
130 個人物分三批匯出，UTF-8 補充平面文字與 CP437 字元正確。修正前測試因 262 次模組解析失敗，
修正後只解析 1 次並通過。

另外對目前完整世界執行隔離匯出，輸出寫入導向測試接收器，不覆寫玩家名稱資料：
1,964 批、128,114 筆名稱及別名，總經過時間 23,422 ms，回呼 CPU 經過計時合計 5,654 ms，
Unicode 模組解析 1 次，起訖圖形 FPS 都為 49。
其中最後整份 JSON 序列化仍有 3,781 ms 的一次性停頓；此次不把它列為已修復。
本次沒有重新載入玩家存檔；完整匯出路徑是在已載入的同一世界驗證。
